Two clients · one endpoint

Log it where
you read it.

Every capture method below sends the same small JSON body to the same token-guarded endpoint: the page URL, the page title, and — for the userscript — the visible heading. The server re-parses the URL, so a layout change can cost you the title but never the chapter number.

Before you start 2 values

The PC clients need both strings below; the iPhone Shortcut needs only the Worker's address, because the app does the posting. Find both in the app under Settings → Sync.

  • Worker endpoint — https://<worker>.<you>.workers.dev/api
  • Sync token — the SYNC_TOKEN secret you set with wrangler secret put SYNC_TOKEN
The token is a password. It lives in this browser's IndexedDB and in Tampermonkey's storage — never in the iPhone Shortcut, which only opens a link. Rotate it with wrangler secret put SYNC_TOKEN if it leaks, then paste the new one into the app and the userscript.

iPhone · Safari Shortcut 2 taps

The Shortcut does one thing: opens a link into Yomi. The app reads the shared page and does the posting itself with the token it already holds, so the shortcut needs no headers, no JSON body and no token — there is nothing in it to get wrong.

Your capture link

https://<worker>/c/

Shown with this Worker's own address, because you are reading this page from it. The shared page URL is appended to the path, after /c/, so no query string can lose it on the way.

Build it once

  1. Open Shortcuts → + and name it Log chapter.
  2. Tap the shortcut's (i) / details panel → enable Show in Share Sheet. Set the accepted input to URLs and Safari web pages.
  3. Add Get URLs from Input and set its input to Shortcut Input. This is the step that matters: a shared Safari page is a page object whose default text is its title, and this action turns it into the address.
  4. Add URL Encode and set its input to the URLs variable from the step above — not to Shortcut Input.
  5. Add Get Details of Safari Web Pages, keep the property Name, then add a second URL Encode for it. That is the page's real title.
  6. Optional, for the total. Add Run JavaScript on Web Page, paste the snippet below into it, then add a third URL Encode for its result. This step has to sit above the Text step: Shortcuts runs top to bottom, and a variable from an action further down is still empty.
  7. Add Text, type the capture link, insert the first URL Encoded Text directly after the final /c/, type ?title=, then insert the second URL Encoded Text. Both share that name — the lower one in the picker is the page title. If you added the total step, type &total= after it and insert the third URL Encoded Text.
  8. Add Open URLs and point it at that Text.
  9. Test: open a chapter in Safari → Share → Log chapter. Yomi opens on the log and shows Logged ch. … with an Undo.

Why the page name is worth the extra step

A brand-new series is otherwise named from the URL slug — usually right, and one rename away from perfect. The name also feeds cover matching, which searches the title you see on the page rather than a slug. On MangaDot this step is not optional: a chapter lives at /chapter/265763, a database id with no series name and no chapter number in the path, so the page name is the only source for both. You never need Run JavaScript on Web Page for the chapter itself: the app parses the URL and the chapter number locally. The one thing it buys you is the series total below.

Sharing a plain link (from Messages, say) instead of a Safari page carries no name, so that step comes up empty. Nothing breaks: the capture still logs and the series falls back to the slug.

The total step, precisely

AniList reports chapters: null for every releasing series, so nothing can look the number up for you. The page you are already reading prints it, and this snippet reads it from there — the same list the PC userscript sends. In the shortcut's details panel, turn on Allow Running Scripts, and allow access to the site once when iOS asks. 

(() => {
  const tally = new Map();
  for (const row of (document.body.innerText || '').split(/\n+/)) {
    const m = /^\s*(\d{1,6}(?:[.,]\d{1,2})?)\s*\/\s*(\d{1,6}(?:[.,]\d{1,2})?)\s*$/.exec(row);
    if (!m) continue;
    const total = Number(m[2].replace(',', '.'));
    if (Number.isFinite(total) && total > 0) tally.set(total, (tally.get(total) || 0) + 1);
  }
  let best = 0;
  let seen = 2;
  for (const [total, count] of tally) {
    if (count > seen) { seen = count; best = total; }
  }
  return best ? String(best) : '';
})()

Only a denominator three or more rows agree on counts, so a stray “1 / 4” from a page counter is ignored. A total the page prints below the chapter you are on is dropped too. Leave the step out and Yomi still logs the chapter — you just type the total once on the series page.

If it says “this device only”

iOS keeps the Home Screen app's storage separate from Safari's. Sharing while you read in Safari opens the Safari copy of Yomi, which has no token yet. The capture still saves — it just stays on the phone until you press Connect and paste the token there once. After that, every share lands straight in the log.

  • The panel shows the address ending at /c/ — the Shortcut sent nothing after the prefix. Open the Text action: the URL variable has to sit on the same line as /c/, with no Return before it, because Open URLs only opens the first URL it finds. If it still lands on its own line, add Get Item from List (First Item) after URL Encode and insert that instead. Run it from Safari's Share Sheet, and set If there is no input to Stop.
  • “The link arrived, but its value was not a page URL” — the page title came through instead of the link, because URL Encode is reading Shortcut Input rather than the URL. Insert Get URLs from Input before it.
  • Nothing opens, or “nothing followed /c/” — the Text is missing the encoded URL after /c/, or the input was not URL-encoded. Re-add URL Encode.
  • “Already in the log” — that chapter was captured before; append-only, nothing overwritten.
  • Series named oddly — it came from the URL slug. Rename it once on the series page; later captures follow the rename.

PC · userscript zero taps

Tampermonkey or Violentmonkey runs the script on chapter pages and posts once per URL. Single-page-app route changes are caught, and a failed request is queued and retried.

Install userscript

  1. Install Tampermonkey (or Violentmonkey), then open the link above and confirm the install.
  2. Open the extension's menu for this script and run Yomi: set Worker endpoint, then Yomi: set sync token.
  3. Read a chapter normally. A small paper card in the bottom-right says Yomi · logged. Nothing else changes on the page.
  4. Use Yomi: auto-log OFF if you open chapters just to check comments; then log this page now becomes the one-tap action.
Only your own reading. The script fires once when you open a page you chose, stores no page content, and sends nothing else. If a site's terms forbid automated access, use the manual method instead — the log still works.

Desktop fallback · bookmarklet 1 tap

The floor always works

Paste a URL

ADD in the app takes a chapter or series URL, parses it locally, and shows you the title before it saves. Works offline, on both devices.

Press +1

Every row has a +1. It logs the next chapter with no network and no parsing. When a site changes its markup, this is the button that still works.

Verify a client 30 seconds

  1. Open Settings → Sync and press Test connection. A green ✓ means the URL and token are right.
  2. Capture one chapter from the client, then focus the PWA. It should arrive within a few seconds.
  3. If it does not, a 500 with “no such table” in the logs means the D1 schema was never applied — run npm run worker:db:remote, then retry.

Yomi keeps one append-only event per (series, chapter, source). Capturing the same chapter twice is always reported as a duplicate, never double-counted.
